1. **Ordem estrita.** Fazer as tarefas pela ordem; cada tarefa assume só as anteriores. Marcar `[x]` no fim. Cada tarefa = 15–60 min.
2. **Nada sai do Mac.** Proibido: `git push`, `git merge` para `main`, `deploy.sh`, `ssh` ao VPS, qualquer ligação ao MongoDB Atlas, enviar emails/mensagens. Tudo fica no ramo local `crm-purple-house` até o dono aprovar.
3. **TDD em todas as tarefas de domínio, API e módulos puros:** escrever o teste → correr e ver falhar **pelo motivo esperado** (indicado em cada tarefa) → implementar o mínimo → ver passar → correr a bateria do CRM (`tests/crm` e/ou `src/lib/crm`).

   - esperas sempre limitadas (`curl --max-time 3`, ciclo com limite de tentativas / ferramenta Monitor); nunca `sleep` solto em primeiro plano;

## 4. API (F1–F2)

**Convenções**
- Prefixo `/api/crm`. JSON. Sucesso devolve o objeto/lista diretamente (estilo do portal, sem `{"dados":…}`); criar → **201**.
- Erro do CRM: `{"detail": {"codigo": "...", "mensagem": "texto pt-PT", "campos"?: {campo: mensagem}, "lojas"?: [...]}}`.
- Erros herdados (`faturacao.auth` / `HTTPBearer`): sem cabeçalho → **403** `{"detail": "Not authenticated"}`; token inválido/expirado → **401** `{"detail": "Sessão inválida ou expirada"}`; conta apagada ou sessão anterior à troca de palavra-passe → **401** `{"detail": "Sessão terminada"}`.

**Códigos de erro do CRM**

| Código | HTTP | Mensagem exata |
|---|---|---|
| `json_invalido` | 400 | "O pedido não é JSON válido." |
| `sem_acesso_crm` | 403 | "Sem acesso ao CRM." |
| `sem_permissao` | 403 | "Sem permissão para esta ação." |
| `nao_encontrado` | 404 | "Loja não encontrada." / "Região não encontrada." / "Membro não encontrado." |
| `validacao` | 422 | "Verifique os campos assinalados." + `campos` |
| `duplicado` | 409 | "Já existe {nome} aqui — é a mesma?" + `lojas: [{id, nome, distancia_m}]` |
| `conflito` | 409 | "Alterado por outra pessoa — recarregar" |
| `regiao_repetida` | 409 | "Já existe uma região com este nome." |
| `regiao_com_lojas` | 409 | "Esta região tem lojas — mude-lhe o nome em vez de a apagar." |
| `loja_com_historico` | 409 | "Esta loja tem histórico — mude a fase para perdida em vez de a apagar." |
| `ja_membro` | 409 | "Esta pessoa já é membro do CRM." |
| `admin_master` | 409 | "O administrador principal já é admin do CRM." |
| `morada_indisponivel` | 503 | pesquisa: "Pesquisa de morada indisponível — coloque o pino no mapa ou use 'Estou nesta loja'"; inversa: "Morada sugerida indisponível — escreva a morada à mão." |

## 10. Armadilhas de portagem (referência rápida)

- PHP `round` → `arredondar` (meio-para-longe-do-zero); `mb_strlen` → `len`; `strlen` → `len(s.encode("utf-8"))`; `in_array(…, true)` → `isinstance(x, str) and x in ORDEM`; `array_is_list` → `isinstance(x, list)`; `preg_match('/…/D')` → `re.fullmatch`; `sprintf('%.6F')` → `f"{x:.6f}"` (depois de `arredondar`); `rawurlencode` → `urllib.parse.quote(chave, safe="")`; `http_build_query(…, RFC3986)` → `urllib.parse.urlencode(…, quote_via=quote)`.
- Testes PHP com `DataProvider`/`yield 'nome' => [...]` → `@pytest.mark.parametrize(..., ids=[...])` com os mesmos nomes pt-PT.
- `node:test` → Jest: `test`/`describe` iguais; `assert.equal` → `expect(a).toBe(b)`; `deepEqual` → `toEqual`; `throws` → `toThrow`; `rejects` → `await expect(p).rejects…`; `mock.timers` → `jest.useFakeTimers()`; `mock.fn` → `jest.fn()`; imports relativos sem `@/`.
- Jest do CRA 5 (`resetMocks: true`): criar `jest.fn` e falsos DENTRO de cada teste ou em `beforeEach` — o CRA usa `resetMocks`, que apaga antes de cada teste a implementação dos criados ao nível do módulo (correções, linha "§10 armadilhas Jest / T1.10").
- Corrotinas nos testes do CRM: `correr(coro)` de `tests/crm/duplos.py` (ciclo novo, sem `set_event_loop`) — **nunca** `asyncio.run`, que deixa a thread principal sem ciclo e parte os testes antigos com `get_event_loop()` (correções, linha do §10; guardado por `test_duplos.py`); rotas por `TestClient` com `dependency_overrides[utilizador_atual]` e `monkeypatch.setattr(crm.db, "obter_db", lambda: base)`.
